# Tile catalog

Developer reference for the tile types a `grid` config can place. The narrative
version, with a render of each tile, is on the
[MyoAssist site](https://neumovelab.github.io/myoassist/modeling/terrains/tile-types).

All sizes and heights are in meters. Angles are in **degrees** where a parameter
name says so (`angle_deg`); no tile parameter is in radians.

Every tile presents a flat top at its declared `base_height` around its whole
perimeter, so connectors join it cleanly. `gap` is the single exception: its trench
mouth reaches the tile edge, which is the point of the tile.
`tests/test_surface_contract.py` measures this by ray-casting the compiled model.

Each tile also reports its own surface height, which is what the velocity map and
`surface_height_at` use. `emit` and `surface_height` live side by side in the tile
module and share the same span arithmetic, so they cannot describe different
geometry.

The tables below are generated from the registry by
`utils/docs/_gen_tile_catalog.py`. Edit a tile module's `PARAM_DOCS`,
`DEFAULT_PARAMS` or `PARAM_RANGES` and re-run it; a test fails if they disagree.

## Notes that do not fit in a table

**`axis` means different things for different tiles.** For `stairs` and `slope`,
`axis` is the direction the feature *progresses* along, so `axis="y"` means you
cross the steps or the ramp while traveling in y. For `gap`, `axis` is the
direction the trench *runs*, so `axis="y"` means the trench is invariant along y
and you cross it traveling in x. The two conventions are opposite; a
`randomization.param_ranges` entry pinning `axis` across types will not orient them
consistently.

**`step_width` auto-fill.** Leaving `stairs.step_width` unset computes
`(long - peak_width) / (2 * n_steps + 2)`, which reserves exactly one tread of flat
landing at each end of the tile. That keeps the first riser off the tile boundary,
where it would put a `step_height` wall against the connector.

**`base_height` has a floor.** Tile geometry extends down to `BASELINE_Z = -2.0`,
so a `base_height` at or below that leaves no room and is rejected. Inverted
variants also need their pit floor to stay above it.

**List-valued parameters cannot be randomized.** `size_range` and `height_range`
take `[lo, hi]` lists, which a `param_ranges` entry would read as a range to sample
from and replace with a single number. Set them directly in the tile's `params`.
Attempting to randomize one is rejected with a message saying so.
